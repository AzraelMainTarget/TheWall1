# Access Worker — 5 минут, с телефона

Проверяет часовые ключи Alpha Test **на сервере**, а не в браузере.
Пока не поднят — сайт работает как сейчас (проверка локальная). После — таймер
нельзя обнулить из консоли: час живёт в Cloudflare KV.

---

## 1. Создать воркер

1. Cloudflare → **Workers & Pages** → **Create** → **Worker**.
2. Имя: `access` → **Deploy** (пока с кодом по умолчанию).
3. **Edit code** → выделить всё → вставить целиком файл **`access-worker.js`** → **Deploy**.

## 2. Создать хранилище ключей

1. **Storage & Databases** → **KV** → **Create namespace**.
2. Имя: `ACCESS` → Create.

## 3. Привязать KV к воркеру

1. Воркер `access` → **Settings** → **Bindings** → **Add** → **KV namespace**.
2. Variable name: `ACCESS` (ровно так, большими).
3. KV namespace: тот, что создал → **Save**.

## 4. Задать свой токен (для закрытия ключей вручную)

1. Там же **Settings** → **Variables and Secrets** → **Add**.
2. Type: **Secret**, Name: `ADMIN_TOKEN`, Value: длинная случайная строка.
3. **Deploy**.

## 5. Проверить

Открой в браузере:

```
https://<имя>.workers.dev/health
```

Должно быть: `{"ok":true,"service":"that-darkness-access","kv":true,"v":1}`
Если `"kv":false` — привязка не сохранилась, повтори шаг 3.

## 6. Включить на сайте

Скажи мне адрес воркера — я пропишу его в `alpha.html` и `guard.js`
и включу серверную проверку. Одна строка:

```js
window.TD_ACCESS_API = 'https://access.<твой-поддомен>.workers.dev';
```

## Что умеет

| Маршрут | Что делает |
|---|---|
| `POST /activate {key, device}` | первая активация: час стартует здесь |
| `GET /check?key&device` | сколько осталось (сервер — источник истины) |
| `POST /revoke {key}` + `Bearer ADMIN_TOKEN` | закрыть ключ досрочно |
| `GET /health` | живой ли и привязан ли KV |

## Как защищает

- Формат и контрольная цифра — битый ключ не пройдёт.
- Час выпуска не старше 48 часов.
- **Ключ одноразовый:** первый активировавший забирает его, второму `already_used`.
- Чужое устройство получает `other_device`.
- Час живёт в KV и не зависит от браузера.
- По истечении ключ помечается `spent` — повторный ввод не пускает.
- `ADMIN_TOKEN` живёт только в Cloudflare, в коде сайта его нет.

## Если что-то не так

- `no_kv` → не привязано хранилище (шаг 3).
- `unauthorized` → неверный или незаданный `ADMIN_TOKEN`.
- `bad_checksum` → ключ собран не нашим генератором.
